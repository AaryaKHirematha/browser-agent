# SIH Demo Presentation Script

## Scene 1: Title
**On Screen:** TRUSTWORTHY AUTONOMOUS BROWSER AGENT - A safety and trust layer for autonomous browser agents
**Presenter Says:** "Welcome. Today we're presenting our Trustworthy Autonomous Browser Agent."
**Key Point:** Establish the project identity.
**Duration:** 6 seconds

## Scene 2: Normal Task
**On Screen:** AI agents can interact with websites...
**Presenter Says:** "AI agents can interact with websites, but autonomous browser actions introduce safety, security, privacy and reliability risks. Let's watch the agent perform a normal task. It needs to search for quantum computing."
**Key Point:** The problem and the baseline capability.
**Duration:** 10 seconds

## Scene 3: Adaptive Observation
**On Screen:** Adaptive Observation Engine with 5 modes.
**Presenter Says:** "The agent dynamically chooses how much information it needs from the webpage. STATE gives a flat list. GRAPH provides structure. DELTA tracks changes. VISUAL adds screenshots."
**Key Point:** Flexible perception.
**Duration:** 15 seconds

## Scene 4: Risk Engine
**On Screen:** Risk assessment of actions (LOW, HIGH, CRITICAL).
**Presenter Says:** "Before any action executes, the Risk Engine evaluates it. Navigation scores LOW. A destructive delete scores HIGH and requires human approval. A financial transaction scores CRITICAL."
**Key Point:** Actions are evaluated before execution.
**Duration:** 15 seconds

## Scene 5: Policy Engine
**On Screen:** Domain-specific policy evaluation.
**Presenter Says:** "Risk alone is not enough. The Policy Engine adds domain-specific rules. For example, reading might be allowed on a banking domain, but all deletions are denied by policy."
**Key Point:** Domain-specific control.
**Duration:** 10 seconds

## Scene 6: Human Approval Gateway
**On Screen:** Approval paused and evaluated.
**Presenter Says:** "When a high-risk action is proposed, execution pauses. The operator can approve the action, or reject it, permanently blocking it."
**Key Point:** Humans remain in the loop for critical actions.
**Duration:** 15 seconds

## Scene 7: Verification
**On Screen:** Action verification succeeding and failing.
**Presenter Says:** "After every action, the Verification Engine takes a post-action snapshot and compares. It doesn't assume success just because the command was sent."
**Key Point:** Closed-loop execution.
**Duration:** 10 seconds

## Scene 8: Self-Healing Recovery
**On Screen:** DOM mutation causing failure, then recovery.
**Presenter Says:** "Webpages are dynamic. If the agent's target element disappears, the Recovery Engine re-observes and semantically re-matches the target."
**Key Point:** Resilience against dynamic UIs.
**Duration:** 15 seconds

## Scene 9: Prompt Injection Defense
**On Screen:** Malicious comments detected.
**Presenter Says:** "Malicious webpages can embed text that looks like instructions. The Prompt Injection Detector scans every observation before it reaches the language model."
**Key Point:** Security against untrusted inputs.
**Duration:** 10 seconds

## Scene 10: Privacy Shield
**On Screen:** Sensitive data redacted.
**Presenter Says:** "When the agent observes a page containing sensitive data, the Privacy Shield redacts them locally. The agent's view replaces sensitive values with REDACTED markers."
**Key Point:** Privacy preservation.
**Duration:** 12 seconds

## Scene 11: Task Memory
**On Screen:** Session scoped task memory.
**Presenter Says:** "The agent maintains session-scoped task memory to provide context throughout execution."
**Key Point:** Continuity of actions.
**Duration:** 6 seconds

## Scene 12: Audit Log
**On Screen:** Audit events list.
**Presenter Says:** "Every decision, risk assessment, and approval is recorded in a structured audit log."
**Key Point:** Accountability and transparency.
**Duration:** 10 seconds

## Scene 13: Performance
**On Screen:** Latency and benchmark numbers.
**Presenter Says:** "The safety layer adds minimal overhead, as verified by automated benchmarks."
**Key Point:** Production viability.
**Duration:** 10 seconds

## Scene 14: Remote MCP
**On Screen:** Remote MCP Architecture.
**Presenter Says:** "The Browser Agent exposes a standards-based remote MCP interface. Designed for interoperability with MCP-compatible AI agents."
**Key Point:** Interoperability with modern AI standards.
**Duration:** 10 seconds

## Scene 15: Technology Stack
**On Screen:** Tech Stack grid.
**Presenter Says:** "The safety layer is built on Node.js, TypeScript, and Chrome Extension MV3."
**Key Point:** Standard, modern tech stack.
**Duration:** 5 seconds

## Scene 16: Conclusion
**On Screen:** Don't just automate the browser. Make browser agents trustworthy.
**Presenter Says:** "Making Browser Agents Trustworthy. Don't just automate the browser. Make browser agents trustworthy."
**Key Point:** Final impact.
**Duration:** 10 seconds
